# 專案 ER 圖與中英文對照

建議先用瀏覽器開啟 `index.html`。圖已內嵌，單一 HTML 檔即可離線閱讀，並可搜尋中文或英文。若要點圖開啟可放大的 SVG，請將 SVG 檔一起保留在相同目錄。

## 檔案

- `00-overview.svg` / `.png`：主要業務流程總覽，只列主鍵、外鍵及單欄唯一鍵，省略部分交叉關聯。
- `01-core.svg` / `.png`：會員、活動、報名、付款及退款通知的完整欄位。
- `02-cancellations.svg` / `.png`：管理員個別取消報名歷程與 Email、LINE 通知。
- `03-accounts-comments.svg` / `.png`：會員停權、密碼重設及活動留言。
- `04-support.svg` / `.png`：未設定實體外鍵的權杖、通知、留言限制及 Flyway 系統表。
- `欄位中英文對照.md`：17 張表、160 個欄位的中英文、型別、空值、鍵與關聯說明。
- `schema.json`：僅含資料庫結構中繼資料，沒有任何會員、交易資料列或連線憑證。
- `generate_erd.py`：依結構快照重新產生 SVG、HTML 與 Markdown；執行 `python notes/erd/generate_erd.py`。PNG 是 SVG 的另行轉圖輸出，腳本不會自動更新 PNG。

## 來源與閱讀注意

結構核對日期：2026-11-23。本機測試資料庫的目前結構對應 V20，共 16 張業務資料表、1 張 Flyway 系統表、16 條實體外鍵。

英文識別名稱保留原樣；中文以目前資料庫 COMMENT 為基礎，缺少說明的欄位由 migration 及程式用途補充。這次僅產生說明文件，未修改資料庫 COMMENT、資料列、正式 migration 或應用程式。

- PK：主鍵；FK：資料庫外鍵；UQ：單欄唯一。複合唯一限制另外列明，不表示個別欄位各自唯一。
- `1 → 0..N`：一筆父資料可以對應零至多筆子資料；`1 → 0..1`：零或一筆。
- 沒有外鍵的表仍可能透過編號產生業務關聯；HTML 已分別說明，不以實線表示。
- 停權表、取消歷程表的會員與管理員角色不同；圖上合併兩條往會員表的路徑並註明，完整欄位對照仍逐一列出兩條外鍵。
- `payments.refunded_at` 依 `PaymentLifecycle` 實際行為說明為「後台標記已退款時間」。既有資料庫 COMMENT 為「退款完成時間」，不應解讀為金流執行或玩家入帳時間。本次未更動既有 COMMENT。
- `comment_write_limits` 的 BIGINT 時間欄位是毫秒時間戳，與其他表的 DATETIME 不同。

資料庫未來增加欄位或 migration 時，須先更新結構快照，再重新產生並檢查圖檔；這些圖不會隨資料庫自動更新。

# 可選 AI 審核與詞庫降級

更新日期：2026-11-21。實作於本機，尚未部署 AWS。

## 發布流程

1. 原有權限、格式、長度與留言頻率檢查仍生效。
2. 詞庫先檢查所有本次公開內容；命中立即拒絕，不呼叫 AI。
3. AI 開啟且金鑰已設定時，再送公開內容到 OpenAI Moderation API。
4. AI 明確拒絕：回應通用拒絕訊息、保留草稿；不切換成故障放行。
5. AI 關閉、金鑰缺少、連線逾時、HTTP 錯誤（含模型停止支援、驗證錯誤、限流）或回應格式無效：退回已完成的詞庫檢查，繼續原本的發布流程。

沒有建立人工待審佇列，也不會因 AI 故障停用登入、瀏覽或報名。

## 開關與設定

預設 AI 關閉，沒有 API 金鑰也能啟動。

在本機或 AWS 的 .env 設定後，重新啟動該環境的 Spring Boot 服務：

~~~dotenv
AI_MODERATION_ENABLED=true
OPENAI_MODERATION_API_KEY=請自行填入API金鑰
AI_MODERATION_MODEL=omni-moderation-latest
~~~

停用時改成 AI_MODERATION_ENABLED=false 並重啟。開關目前透過環境設定管理，後台提供狀態顯示與重新整理，不提供修改金鑰或開關的表單。

不要將實際金鑰貼到聊天室、放入前端或提交 Git。測試設定強制關閉 AI，使用模擬供應商驗證行為，不讀取真實金鑰或送出網路請求。

## 故障等待與恢復

- 連線逾時 2 秒；單次請求逾時 3 秒。
- 不立即重試，故障後 60 秒內僅使用詞庫。
- 60 秒後由下一次發布請求嘗試 AI；恢復正常後自動回到雙重檢查。
- 後台活動管理頁顯示關閉、未設定、等待首次審核、正常或故障降級狀態；可手動重新整理。成功載入後台與儲存活動後亦會更新。
- GET /admin/moderation/status 僅允許管理員 Session，回應不含金鑰、原文或供應商回應。
- 日誌只記錄安全的錯誤類型或 HTTP 狀態碼，不記錄原文、金鑰或第三方完整回應。

## AI 的封鎖分類

採用 OpenAI Moderation 的以下分類：

- harassment
- harassment/threatening
- hate
- hate/threatening
- sexual/minors

不因整體 flagged=true 就一律封鎖；一般 violence 或 violence/graphic 分類不單獨觸發拒絕，以免把正常奇幻戰鬥一律擋掉。其他分類未列為本版封鎖條件。

這是網站自行選擇的審核政策，不是模型對 D&D 語境完全不會誤判的保證。若服務仍正常但模型判定變嚴格，系統不會因此自動認定為故障；可手動關閉 AI，並以跑團案例重新驗收。

官方介面文件：https://developers.openai.com/api/docs/guides/moderation

## 傳送內容與限制

- 留言發表及編輯送出留言本文；活動公開欄位與標籤合併成一次審核。
- 不另外附帶會員帳號、Email、密碼、登入 Token 或內部管理資料。使用者自行填在公開文字裡的內容仍會隨該文字送審。
- AI 故障時會放行通過詞庫的內容，因此詞庫未涵蓋的不當內容可能通過；這是本專案採用的可用性優先降級策略。
- 不會回頭批次審核已發布內容。
- 透過 AiModerationGateway 介面可替換供應商；模型名稱可透過設定更換。

## 驗證範圍

模擬案例包含：正常通過、明確拒絕、關閉、缺少金鑰、逾時、模型 404、驗證失敗、供應商限流、伺服器錯誤、無效 JSON／分類欄位、60 秒後恢復，以及詞庫在降級期間仍有效。

另驗證後台狀態的管理員權限、草稿保留與原有流程回歸。尚未使用真實 API 金鑰測試外部服務，不能宣稱已完成真實 AI 準確度或可用性驗收。

驗證結果：後端完整回歸 95 項通過；補充後的 AI 降級單元測試 8 項全部通過（其中 7 項已包含在完整回歸內）；前端 28 項通過，26 個 JavaScript 檔案語法檢查通過。未呼叫真實外部 API，未部署 AWS。

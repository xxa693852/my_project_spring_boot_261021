# 第三批追加需求：欄位即時計數

狀態：第三批已在本機實作並完成自動化驗證，尚未部署 AWS。

- 註冊頁：姓名或暱稱顯示目前字數／30，帳號顯示目前字數／20。
- 活動新增／修改共用表單：活動名稱／100、活動介紹／5000、主持人／50、地點／255；輸入、貼上、刪除與載入既有資料時同步更新。
- 自訂標籤：顯示標籤數／5，並協助辨識每個標籤是否超過 16 字元。
- 沿用既有留言介面的即時計數體驗，計數口徑須與前後端長度驗證一致。
- 所有密碼相關欄位一律排除：註冊密碼、確認密碼、修改密碼的舊／新／確認、重設密碼及登入密碼。即使切換顯示密碼，也不得出現字數計數。
- 電子信箱沿用使用者要求的收信提示，不重新顯示 254 字元上限；目前也不加入會帶出該上限的計數。
- 保留原有字數上限、格式驗證與 API 規則；數字、日期、唯讀欄位不加入文字計數。
- 完成時確認桌面／手機版面與輔助說明，不讓每次輸入造成過多提示。

## 第三批完成內容與驗收紀錄

- 留言發表與新增的編輯 API 最多 500 字元；只有作者可編輯，活動取消／結束或留言被隱藏時不得編輯。
- 留言及活動新增／修改的名稱、介紹、主持人、地點與標籤共用 PublicContentPolicy。拒絕訊息固定為「內容不符合發布規範，請調整後再試。」，不包含命中詞、欄位或位置。
- 初始詞庫僅列少量明確辱罵詞；可由 app.moderation.blocked-terms 以逗號分隔覆寫。以 Unicode NFKC 正規化並略過空白、標點與不可見格式字元比對，不改寫原文。這是詞庫檢查，並非理解語境的分類模型。
- 測試確認屠龍、邪教、殺死敵人、死亡豁免、刺客、血魔法、幹掉哥布林、幹練等用語通過。
- 同一會員跨活動共用：嘗試間隔 2 秒、固定 60 秒視窗最多 10 次；失敗驗證與格式錯誤也計入。超限回應 HTTP 429 與中文訊息。
- 發表間隔 30 秒、編輯間隔 10 秒，共用最後一次寫入時間；刪除不清除限流狀態。通過權限與內容檢查後預約寫入，後續資料庫失敗亦保留冷卻。
- V16 建立 comment_write_limits；獨立交易加上列鎖保存嘗試與冷卻，與留言資料分開，重啟不會清空。既有 V1～V15 未修改。部署前需照慣例備份資料庫。
- 發表、編輯與活動儲存遭拒不清除草稿；留言請求等待時暫停欄位操作，防止成功回應清掉等待期間的新輸入。
- 姓名／帳號、活動名稱／介紹／主持人／地點、標籤、留言發表／編輯與隱藏原因加入計數。密碼、確認密碼、舊密碼完全排除；電子信箱不顯示 254 上限或計數。
- 計數以 UTF-16 長度計算，與現有 Java String.length、HTML maxlength 一致；輸入、貼上、刪除、重設與載入既有資料皆更新。
- 後端完整回歸 84 項通過；前端 28 項通過；26 個 JavaScript 檔案語法檢查通過。資料庫案例僅使用 dnd_event_prod_test；一般流程測試停用時間限制，專用 CommentRateLimitTests 真正啟用限流並驗證獨立提交與跨活動行為，完成後清理限流測試紀錄。

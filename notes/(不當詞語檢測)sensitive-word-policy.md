## 使用哪一版？

詞庫維持本專案自行實作的第一版，沒有引用第三方敏感詞套件或外部大型詞庫，因此詞庫沒有第三方版本號。

## 檢查哪些欄位？

| 功能 | 檢查內容 |
| --- | --- |
| 留言發表 | 留言本文 |
| 留言編輯 | 修改後的留言本文 |
| 活動新增 | 活動名稱、介紹、主持人名稱、地點、自訂標籤 |
| 活動修改 | 活動名稱、介紹、主持人名稱、地點、自訂標籤 |

目前沒有把敏感詞檢查套用到註冊帳號、姓名或暱稱、電子信箱、密碼、隱藏留言原因等欄位。各欄位原有的長度、格式與權限驗證仍獨立執行。

不會回頭批次掃描、刪除或改寫既有內容；修改活動時，會檢查本次送出的公開欄位。

## 如何比對？

1. 使用 Unicode NFKC 正規化。
2. 轉為不受地區影響的小寫。
3. 在比對用文字中略過 Unicode 分隔字元、標點與格式控制字元，例如空白、一般標點及零寬空白。
4. 以 contains 檢查是否包含詞庫中的完整字串。
5. 同樣正規化詞庫項目；略過空項目。

以上只處理比對副本，不會將使用者原文改成正規化後的版本。

例如「操 你 媽」或在「幹你娘」中插入零寬空白，仍會被辨識。這不代表能辨識所有符號、諧音、注音、同音字、拆字或其他規避方式。

## 被拒絕時的行為

敏感詞拒絕固定回應 HTTP 400 與下列訊息：

> 內容不符合發布規範，請調整後再試。

不回傳命中詞語、欄位或文字位置。前端保留留言發表、編輯及活動表單的草稿。

長度或格式不符仍使用各自的欄位錯誤提示；留言頻率超限則回應 HTTP 429，這兩者與敏感詞拒絕分開處理。

## 怎麼調整詞庫？

Spring 設定鍵為 app.moderation.blocked-terms，使用半形逗號分隔。例如：

~~~properties
app.moderation.blocked-terms=幹你娘,干你娘,操你媽,操你妈,你媽死了,你妈死了,去你媽的,去你妈的,娘你幹,娘你干
~~~

設定此鍵會整份取代程式的預設詞庫，不是自動追加。調整後須重新啟動應用程式。不要填成空字串，除非確定要停用詞庫比對。

目前沒有後台詞庫管理頁面。修改程式預設值時需重新打包；透過外部 Spring 設定覆寫則不必為了詞庫內容重新編譯。

## 目前限制

- 詞庫很小，僅是初步辱罵詞防護，不是完整內容審核方案。
- 不理解引用、玩笑、角色扮演或上下文；引用被封鎖詞也可能被拒絕。
- 不會自動繁簡轉換，只辨識清單明列的字形及上述正規化結果。
- 沒有涵蓋所有髒話、歧視、性騷擾、廣告或個人資料。
- 後續擴充應逐筆評估，避免加入容易與 D&D 正常敘述重疊的單字。

### 女性稱呼變體補強

詞庫比對時，將比對副本中的「妳」統一視為「你」，因此「娘妳幹」、加空白／標點／零寬字元的寫法，以及既有辱罵詞的「妳」版本，都套用同一規則。使用者原文不會被改寫，一般含「妳」的正常句子仍可發表。

# 第一批：管理員登入與權限隔離

## 完成範圍

- 管理員登入頁：`/admin-login.html`。
- 一般會員登入仍使用既有 JWT 與保持登入流程；會員 Token 即使屬於管理員帳號，也不能取得後台權限。
- 已從專用入口登入的管理員，可沿用同一個 Session 查看自己的報名、修改會員資料與密碼，不需再走會員登入，也不額外簽發長效 Token。前台與後台共用 30 分鐘閒置期限；讀取不續期，寫入驗證 CSRF，且只能操作本人會員 ID。
- 前台載入時先等待伺服器確認身分，再決定是否導向登入，避免管理員因非同步查詢尚未完成而被誤送至會員登入頁。
- 後台改用伺服器端 Session，瀏覽器只持有 HttpOnly、SameSite=Lax 的工作階段 Cookie，不保存長效後台 Token。
- `/admin/**`、活動管理頁與會員管理頁統一由 `AdminAuthInterceptor` 驗證。
- 登入成功更換 Session ID。每次後台請求重新確認會員啟用狀態、管理員角色與停權狀態。
- 閒置滿 30 分鐘失效。前台與後台的實際點擊、輸入、捲動會回報活動時間；單純讀取資料、背景檢查及開著分頁不續期。
- 前台最初不顯示後台入口；專用入口登入成功後，前台才顯示「返回管理後台」。逾時或後台登出後再次隱藏，不打斷會員瀏覽。切回分頁會重新確認狀態，支援 BroadcastChannel 的瀏覽器也會同步其他分頁的後台登入／登出。
- 後台寫入要求 CSRF Token；登入 API 要求專用 Header，沒有開放跨來源 CORS。
- 逾時時在原頁重新登入，未送出的活動、停權、退款與留言管理欄位留在記憶體；不自動重送失敗的操作。同一頁重新登入其他管理員時會重新載入，避免沿用原帳號資料。
- 關閉或重新整理頁面不保證保留草稿；這批的保留範圍是逾時後在原頁重新登入。
- 公開／會員留言入口不回傳隱藏留言。從活動管理的活動表單點「管理活動留言」，才進入獨立管理模式。
- 前台登出會清除後台 Session，再撤銷會員 Token；即使會員 Token 已過期或不存在，也不得保留後台權限。會員登入（包括同一帳號或切換帳號）先清除舊後台 Session，必須重新經專用入口驗證才能再進後台。
- 後台的專用登出只清除管理身分。重啟伺服器後需重新登入後台。

## API

| 路徑 | 用途 |
| --- | --- |
| `POST /admin/auth/login` | 以帳密建立後台登入狀態，需要 `X-Admin-Login: 1` |
| `GET /admin/auth/me` | 讀取後台身分、CSRF Token 與閒置截止時間，不續期 |
| `POST /admin/auth/activity` | 回報實際操作，需要 `X-Admin-CSRF` |
| `POST /admin/auth/logout` | 登出後台，需要 `X-Admin-CSRF` |
| `POST /members/logout-session` | 前台先清除後台 Session，需要 `X-Session-Logout: 1`，不依賴會員 Token |
| `GET /admin/events/{eventId}/comments` | 管理留言清單，包含隱藏原因 |

未登入或逾時的後台 API 回傳 401；已登入但 CSRF 驗證錯誤回傳 403。直接開啟後台 HTML 頁面時，未登入會轉到管理員登入頁。

## 自動驗證

後端：

```powershell
.\mvnw.cmd -o '-Daether.syncContext.named.factory=rwlock-local' test
```

前端流程與草稿保留（最小 DOM 替身，不代表完整瀏覽器測試）：

```powershell
node --test --test-isolation=none src/test/js/admin-auth.test.cjs
```

後端包含模擬時鐘的 30 分鐘邊界測試，以及實際測試資料庫的活動、報名、停權、留言、會員／後台登入獨立性測試。既有資料庫測試會確認使用 `dnd_event_prod_test`，並依既有流程回滾測試資料。

## 本機人工驗收

1. 重啟本機程式，重新整理頁面，直接輸入 `/admin-login.html`，使用既有管理員帳密。
2. 一般會員帳密應無法登入管理後台；管理員帳號從會員入口登入後，仍須另外登入後台。
3. 查看、新增及修改活動，確認會員管理、停權與退款登記仍可使用。
4. 開啟活動表單並輸入未送出內容，閒置 30 分鐘。重新登入同一管理員後，內容應保留，並由使用者再次確認送出。
5. 點「返回前台」，確認前台出現「返回管理後台」，可直接回到後台；只有會員登入時應不出現入口。
6. 在前台實際操作可延續後台登入；閒置逾時後入口應自動消失，前台不跳轉也不彈出管理員登入框。
7. 前台登出後，改登入一般會員，確認沒有返回後台入口，且直接輸入後台頁面／呼叫後台 API 均遭拒絕。
8. 未先登出而直接走會員入口重新登入（相同或不同帳號），也必須清除先前後台權限。

本批未新增資料庫欄位或遷移，也未部署 AWS。

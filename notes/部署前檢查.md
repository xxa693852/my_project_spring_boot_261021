# 部署前檢查

## 活動時間基準

管理頁標示台北時間，只代表表單輸入與顯示的約定；尚未確認 AWS 後端的時間設定一致，不能視為已通過部署驗收。

- 核對 EC2 系統時間與時區，以及實際 systemd 服務啟動的 JVM 預設時區；兩者須分別確認，不能只看 SSH 終端機的時間。
- 現有 API 使用不帶時區的 LocalDateTime。核對伺服器的 LocalDateTime.now()、MySQL/JDBC 的日期讀寫與前端 UTC+08:00 約定一致。
- 使用專用活動實測日期往返不偏移，並驗證報名截止前後及活動開始前後的後端判斷。
- 本項待 AWS 部署前實測；本次未更新 AWS，也未調整伺服器時區或登入規則。

## Flyway 歷史版本

- V1～V13 已在 AWS 套用，維持 db923d7 的父版本原文；連註解也不可回頭修改。
- 新增中文說明放在獨立文件；資料庫 COMMENT 使用 V14，新欄位命名使用 V15。
- HistoricalMigrationIntegrityTests 會驗證 V1～V13 校驗值，避免再次把純註解變更帶入既有版本。
- AWS 若尚未執行 V14、V15，新版首次啟動會新增中文註解並重新命名會員關聯欄位，部署前須備份資料庫。
- 本次保留正式環境 Flyway 驗證，不關閉 validate、不修改 AWS schema_history。
- 本機曾套用註解版的兩個資料庫，已先備份歷史表並僅對已確認 SQL 敘述相同、校驗值符合註解版的 V1～V13 對齊 checksum；業務表未變更。

## 下次 AWS 部署後必測（尚未線上驗收）

- 管理者免費活動報名修正僅完成本機驗證，AWS 尚未測試；部署時提醒使用者一起驗收。
- 從 ngrok 的管理員入口登入 → 前台免費活動報名 → 我的報名 → 取消報名 → 返回管理後台，確認同一身分可正常往返。
- 另測付費活動、前台登出後切換一般會員，確認沒有殘留管理員權限。
- 第二批欄位與新密碼限制也待部署後驗收。

- JWT 唯一性修正尚未部署：新版每次簽發都加入 jti；上線後與第二批一起測試同帳號快速重複登入及一般會員登出。

## 可選 AI 審核

- 預設關閉；只有設定 OPENAI_MODERATION_API_KEY 並開啟 AI_MODERATION_ENABLED=true 後才送審。金鑰僅放伺服器環境設定，不能放前端或提交 Git。
- AI 故障自動退回詞庫，不轉人工、不影響核心功能；明確拒絕不放行。後台活動管理頁可查看狀態。
- 開關修改後重啟才生效。部署後另做真實服務驗收，檢查 D&D 正常敘述、辱罵拒絕、服務逾時降級與草稿保留。

## 本機藍新回呼環境隔離

本機曾將訂單通知與返回頁誤送到 AWS 使用的 ngrok；實際通知回應為 400「查無付款訂單。」。目前僅清空本機 .env 的 NEWEBPAY_TEST_CALLBACK_BASE_URL，重啟本機服務後會停止建立付費測試訂單，直到設定獨立且轉向本機 8081 的 HTTPS 網址。AWS 通道仍維持 127.0.0.1:18081，未修改 AWS .env 或部署。此本機空白設定不可隨部署覆蓋到 AWS。
